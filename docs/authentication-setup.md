# إعداد المصادقة في MjTop

## ما تم تجهيزه

المشروع يدعم الآن جلسات Manus OAuth الحالية، ومصادقة محلية للإدارة، وإنشاء جلسة ضيف. أضيفت أيضاً قراءة placeholders لـGoogle Login وFacebook Login. الأزرار تظهر في واجهة الدخول لكنها تبقى معطلة حتى تُضاف مفاتيح OAuth الحقيقية.

## أسرار OAuth

أضف القيم التالية إلى أسرار WebDev، وليس إلى GitHub:

```text
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
FACEBOOK_APP_ID=
FACEBOOK_APP_SECRET=
```

بعد إدخال المفاتيح يجب تنفيذ مسارات OAuth الفعلية الخاصة بكل مزود وتسجيل redirect URI للنطاق النهائي. القيم الحالية لا تفعل تسجيل Google أو Facebook؛ هي placeholders آمنة فقط.

## الإدارة المحلية

اسم المستخدم الافتراضي في الإعداد هو `mjtop249@gmail.com`. كلمة المرور لا تُحفظ في الكود أو قاعدة البيانات كنص صريح. يجب إنشاء `ADMIN_PASSWORD_HASH` باستخدام أمر توليد hash الموجود في `.env.example`، ثم حفظ الناتج كسِر في WebDev.

عند أول محاولة دخول صحيحة ينشئ الخادم مستخدم الإدارة المحلي إذا لم يكن موجوداً. المستخدم يحصل على role `admin` وauthProvider `local`، وتُنشأ له جلسة JWT داخل كوكي HttpOnly وSecure عند HTTPS.

كلمة المرور التي ظهرت في المحادثة لم تُضمّن في المشروع أو GitHub. استخدم كلمة مرور جديدة قوية لا تقل عن 12 حرفاً.

## وضع الضيف

زر “الدخول كضيف” ينشئ مستخدماً محدود الصلاحية مع `authProvider=guest` وrole `user` وجلسة قصيرة مدتها 24 ساعة. الضيف لا يستطيع الوصول إلى إجراءات لوحة الإدارة، ولا يمكنه تغيير صلاحياته.

## قواعد التشغيل

لا تضع ملفات `.env` أو المفاتيح الحقيقية داخل المستودع. بعد إضافة الأسرار أعد تشغيل الخادم وشغّل:

```bash
pnpm check
pnpm test
pnpm build
```

يجب إضافة اختبارات OAuth الفعلية بعد تفعيل كل مزود، مع اختبار redirect URI وnonce ورفض state غير الصحيح.
